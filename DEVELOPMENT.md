The user authorizes ongoing improvements until they ask to stop, including commits and pushes to `main` in `ibixina/brain_3d` and deployments through the existing GitHub Pages Actions workflow. Keep the minimal, intuitive, brain-first interface. Do not use ChatGPT hosting, other repository services, paid resources, or fabricated scientific data. An active chat heartbeat named **Continuously improve Cerebra** resumes work every 30 minutes. Its id is `continuously-improve-cerebra`. Reuse it rather than creating duplicates. Local scheduling requires the computer and app to remain running. The user authorizes using an earned full-reset credit when usage becomes low, but limits must not be bypassed and credits must not be purchased.

The installed Codex CLI's generated protocol includes `account/rateLimitResetCredit/consume`. A local, ignored helper is available at `.cache/check_codex_usage.py`. Run `python3 .cache/check_codex_usage.py --redeem-if-low` at the start of a run and when a long run may approach its usage limit. It reads usage through the official local app-server protocol, verifies that the account matches the privately retained app account, and only redeems an existing available credit at 15% remaining or less (or when ordinary usage is blocked). Retried attempts reuse a persisted UUID idempotency key; an explicitly ineligible attempt may be tried later as a new attempt. It never purchases credits or outputs credentials. Seven simulated RPC scenarios checked healthy usage, read-only mode, no available credit, account mismatch, eligible usage, interrupted-request retry, and a later attempt after ineligibility. The latest real check reported 35% remaining, one available reset, and `action: none`; no real credit was spent. Private account configuration and outcome logs remain under `.cache/` and must not be committed. If the helper or verified account configuration is missing, inspect the CLI's generated protocol and use `get_usage_limits`; do not guess methods or bypass the account check.
